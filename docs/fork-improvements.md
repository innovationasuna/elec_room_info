# 参考分支比较与采用记录

日期：2026-10-01。

- 基线：[sxdl/elec_room_info @ c8e2cdd](https://github.com/sxdl/elec_room_info/tree/c8e2cdd)
- 参考：[Hashi-Club/elec_room_info @ 5caa1e9](https://github.com/Hashi-Club/elec_room_info/tree/5caa1e9)
- 本 fork 保留 sxdl 目录结构和运行模式，没有直接合并参考分支的整体重构。

## 采用

1. **环境变量配置思路**：增加 `BEARER_TOKEN` 和 `.env`，兼容已有 YAML，避免要求迁移现有配置。只增加 `python-dotenv`，不替换其余依赖管理和部署方式。
2. **数值化余额**：借鉴其提取浮点数的方向，按 sxdl 的 `map.showData.信息` 结构取文本；支持常见冒号、单位及水费逗号格式。无法识别的数据明确失败，不返回伪造的 0。
3. **Token 获取说明**：补充电脑版一卡通及 Session Storage 的 `access_token` 路径；仍需真实用户验证登录。

## 没有整体移植的原因（代码静态比较）

- Hashi 的 `main.py` 执行一次后退出，定期执行交给 GitHub Actions；直接替换会丢失当前本地持续采集流程。
- 参考分支删除 Docker 文件及原余额/充值监控模块，且未保留原 30 分钟告警节流和充值差分检测；这些原有能力继续保留。
- 其 `query.py` 返回 `showData` 后直接当字符串解析，而 sxdl 原始契约是 `showData['信息']`。当前真实响应结构仍待登录验证，所以测试明确使用上游结构作为模拟输入。
- 参考实现解析 ValueError 时返回 `0.0`，会把解析异常混同为余额耗尽；本 fork 用 `QueryError` 区分失败与合法零值。
- 参考分支 README 描述了用电日报，但本次读取的 `main.py` 只查询并判断阈值，未见日报生成流程；不把 README 宣称当作已实现能力引入。
- Telegram、GitHub 定时任务及云端通知不属于当前本地数据接入范围，不启用、不移植。

## 在当前流程上增加的可靠性修复

- 单次 HTTP 请求默认 20 秒超时，可通过 YAML `query.timeout_seconds` 调整。
- 明确处理 HTTP 和业务 JSON 两层 401/403、无效 JSON、缺少房间绑定/字段及错误文本；不记录原始响应或凭据。
- 原持续循环中捕获查询错误，失败不写 CSV、不对旧数据发提醒，下一周期再试；不新增调度器。
- CSV 最新一行读取原来在每行回调中再次打开并扫描整份文件；改为一次读取后取最后一行，修复测试中观察到的未关闭文件警告，处理只有表头的情况。
- 上次部署准备的本地入口和依赖锁文件一并纳入版本管理。`query` 输出 JSON，错误时保留上次成功快照。

## 验证

13 项 unittest 通过，覆盖配置优先级、空 Token、超时配置、学校原始字典结构、HTTP/业务鉴权失败、网络/JSON/结构异常、合法零值、解析失败、CSV 保留和回写、更新环境 Token 及循环恢复。测试响应均为模拟数据，没有访问学校账户或发送通知。

真实网络探针（此前本地部署）：未带 Token 的学校接口 GET 返回 HTTP 401 / `缺失令牌,鉴权失败`。真实账户余额、校区绑定、Token 有效期和长期运行仍未验证。
